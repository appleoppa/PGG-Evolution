# 三顺序代入方法（核心方法）

> **21354 / 12534 / 14325 不是流程步骤编号，而是 APEX 公式模块编号的代入遍历路径。**
> 出处：`APEX_PROTOCOL_3.md` D1-D5 维度表。这是最容易误解的地方，务必读透。

## 1. 模块编号映射

| 编号 | 模块 | 含义 |
|---|---|---|
| **1** | **Θ** | LLM效能（推理/判断质量） |
| **2** | **K** | 技能掌握（工具预检/熟练度） |
| **3** | **ε** | 自修复（故障自愈能力） |
| **4** | **Φ** | 正反馈（评测/奖励信号） |
| **5** | **Ψ** | 健康状态（系统可观测性） |

## 2. 三条代入路径

| 顺序 | 遍历路径 | 起点视角 |
|---|---|---|
| **21354** | K → Θ → ε → Ψ → Φ | 先看技能，再看效能/自修复/健康/反馈 |
| **12534** | Θ → K → Ψ → ε → Φ | 先看效能，再看技能/健康/自修复/反馈 |
| **14325** | Θ → Φ → ε → K → Ψ | 先看效能，再看反馈/自修复/技能/健康 |

## 3. 怎么用（每遍 5 步）

对当前真实任务，按顺序遍历 5 个模块，每模块回答：

1. **代入点**：这个模块在这个任务里具体指什么？
2. **触发判断**：有没有短板信号？
3. **暴露信号**：暴露了什么具体问题？
4. **观察**：证据是什么？

**关键规则**：
- 每条路径换起点 → 防止"只看一个维度好了就以为全好"
- 每个顺序各跑 5 遍（形成 5 组观察）
- 三个顺序都要跑（21354×5 + 12534×5 + 14325×5）

## 4. 实战示例（本地法条检索优化，2026-09）

用 21354（K→Θ→ε→Ψ→Φ）代入：

| 模块 | 代入点 | 暴露的短板 |
|---|---|---|
| **K 技能掌握** | 调用检索工具前 | 没做状态预检，直接撞 fail-closed |
| **Θ LLM效能** | 罪名映射环节 | 纯规则匹配，无 LLM 语义层 |
| **ε 自修复** | 故障后 | 有修复工具但没自动触发，回路断裂 |
| **Ψ 健康状态** | 检索系统 | 哈希漂移无报警，健康不可观测 |
| **Φ 正反馈** | 评测环节 | 12条样例 100% 是过拟合假阳性（holdout 证实） |

换 12534（Θ→K→Ψ→ε→Φ）再看，新增视角：
- **Θ**：检索长查询 ngram 膨胀问题
- **K**：调工具前应先 `--health`

三个顺序交叉覆盖后，短板清单更完整——这就是三顺序的意义。

## 5. 常见错误

❌ 把 21354 当成"第1步做2、第2步做1..."的流程步骤
✅ 它是**公式内模块的遍历顺序**：从不同起点审视同一组能力模块

## 6. 工具化

```bash
# 用插件执行三顺序代入
python3 scripts/self_evolve.py --substitute <task> --order 21354
python3 scripts/self_evolve.py --substitute <task> --order 12534
python3 scripts/self_evolve.py --substitute <task> --order 14325
```
