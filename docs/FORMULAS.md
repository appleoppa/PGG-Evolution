## 4. EVM 治理公式（短板→缺陷映射）

```
EVM = E×V×M×A×Base × Ancient × (1 - defect_rate)

defect_rate = avg(defects)×0.5 + boost_coeff × max(defects)^1.5
```

- **E×V×M×A**：熵(Entropy)、活力(Vibe)、物质(Matter)、行动(Action)
- **Base**：基础状态（工具/环境）
- **Ancient**：古老智慧因子，是 6 个命名系数的乘积（道德经/易经/黄帝内经/河图洛书/天干地支/五行）。**它在乘法链里**，但默认值全为 `1.0`（数值中性）：不调参时 EVM 数值等于 `E×V×M×A×Base×(1-defect_rate)`；原始实现的 `apply_ancient_wisdom()` 可把它抬到 >1（实测 1.15）。
  **但它是人为设定的命名映射，不是实测校准量**：只可作分区、归类、复盘线索，不得作为能力证据或评测分数来源。把 EVM 当可测指标时，只用 `E×V×M×A×Base×(1-defect_rate)` 这段有定义的乘积。
- **defect_rate**：缺陷率惩罚，越大越拉低 EVM

**EVM 的职责**：把已暴露短板映射为可治理缺陷，比较补齐前后变化。
**不得用 EVM 分数预设短板**——先真实代入任务暴露短板，再算分。

## 5. 公式使用纪律

1. **公式是诊断排序器，不是结论生成器**
2. **先暴露短板，再代入公式**（禁止反着来）
3. **分数不能抵消硬门禁**（VERIFIED 需真实闭环证据）
4. **同一治理系数不能重复自证**（评估器必须先审自己）

## 最大短板非线性惩罚（吸收自 EVM 仓库）

来源：`3.EVM-Entropy-Vibe-Mathing仓库/CoreFormula/EVM_FORMULA.py` v1.2。

```bash
python3 scripts/self_evolve.py --defect-rate "Tok=0.8" --defect-total 12
python3 scripts/self_evolve.py --defect-rate "Tok=0.2,Clw=0.2,Agt=0.2,Pan=0.2" --defect-total 12
```

```
defect_rate = avg(defects) * 0.5 + boost_coeff * max(defects) ** 1.5
boost_coeff = 0.15
```

**为什么不用纯平均**：纯平均会**稀释**单一重大短板——9 个指标完美 + 1 个崩盘，
平均值看着还行，系统实际已不可用。非线性项让「最大短板」获得相称权重。

**实测（本次，分母 12）**：

| 场景 | 缺陷率 |
|---|---|
| 单一大短板 0.8 | **0.140665** |
| 同总量分散为 0.2 × 4 | **0.046750** |
| 中等 0.4 | **0.054614** |

集中单点的惩罚约为分散四点的 **3.0 倍** —— 系统承压看最弱环，不看平均值。

### 口径纪律（不得含糊）

上游用**固定 12 维**向量，分母恒为 12。本实现默认分母 = 传入项数，
同输入数值**不同**（默认口径 `Tok=0.8` → 0.507331，非 0.140665）。

因此 CLI 显式暴露 `--defect-total N`：传 12 即完全复现上游口径。
调用方必须知道自己在用哪种口径，不能把一个口径的数字说成另一个口径的。
