# 证据等级账本（E0-E9）：把「文件存在不等于能力完成」变成可执行校验

> 来源：开智与进化成果包 D04《能力证据与验收标准》E0-E9 证据梯度 + D07《无效重复矛盾夸大内容标记归档清单》
> 定位：**这是本框架的诚实性内核。** 门禁（`GATES.md`）管「能不能改」，证据账本管「凭什么说已经成了」。

## 1. 为什么需要它

自进化系统最容易犯的错不是改错代码，而是**把开始说成完成**：

| 常见谎报 | 真相 |
|---|---|
| 「文件写好了」= 功能完成了 | 文件存在只证明文件存在（E1） |
| 「代码里有这个函数」= 能力有了 | 代码存在只证明有这段文本（E2） |
| 「能 import」= 系统可用了 | 加载成功只证明该环境接口可用（E3） |
| 「有测试文件」= 测过了 | 测试存在 ≠ 测试通过（E4 vs E5） |
| 「测试全绿」= 生产可用 | 局部测试通过 ≠ 真实任务闭环（E5 vs E8） |
| 「跑过一次成功」= 长期稳定 | 单次 E8 ≠ E9 |

本框架用**可执行校验**替代口头纪律：登记证据时校验最低要求，读回时**重新核验**并派生**允许的**状态词。

## 2. 十级梯度

| 等级 | 名称 | 登记需提供 | 能证明 | 不能证明 |
|---|---|---|---|---|
| **E0** | 文本主张 | `--note` 主张原文 | 有人提出过某说法 | 实现、性能、部署 |
| **E1** | 文件存在 | `--artifact` 存在的文件 | 某文件在指定时点可定位 | 可解析、可执行、当前有效 |
| **E2** | 代码存在 | `--artifact` + `--note` 符号名 | 指定工作树存在该实现 | 可 import、正确性、被使用 |
| **E3** | import/加载 | `--artifact` + `--verify-cmd` + `--execute` | 该版本在该环境加载接口可用 | 测试通过、入口可执行、已接线 |
| **E4** | 测试存在 | `--artifact` 测试文件 | 覆盖意图存在 | 可收集、通过、充分 |
| **E5** | 测试通过 | `--artifact` + `--verify-cmd` + `--execute` | 指定范围内局部行为通过 | 入口、集成、真实任务、长期稳定 |
| **E6** | 入口可执行 | `--artifact` + `--verify-cmd` + `--execute` | 该入口在该命令范围可运行 | 全部接线、业务价值、生产授权 |
| **E7** | 运行时接线 | `--artifact` 含 trace/接线/调用链 特征 | 指定运行路径确实使用该组件 | 真实任务已验收、广泛稳定 |
| **E8** | 真实任务闭环 | `--artifact` 含 task/receipt/回执 特征 | 限定任务/环境/风险范围完成闭环 | 对其他任务/版本/环境泛化 |
| **E9** | 长期稳定/外部评测 | `--artifact` 含 **≥2 次** run/repro/复现 | 限定期间、任务集、协议下稳定 | AGI、ASI、零错误、职业替代 |

## 3. 硬规则

1. **不跳级**：高等级必须能回溯到低等级。`E8` 必须同时具备 `E2+E3+E5+E6+E7`；只有 `E8` 而无前置 → 判 `PARTIAL`，不判 `VERIFIED`。
2. **命令不自动重跑**：`E3/E5/E6` 登记时需 `--execute` 显式授权才真跑；读回时若不带 `--execute`，这些等级**保守失效**（不得凭旧回执冒充现状）。
3. **工件失效即降级**：读回会重新核验工件。文件被删/被改，对应等级立即失效并进 `stale_levels`。
4. **空文件不算证据**：`E7/E8/E9` 要求工件含最低内容特征，`E9` 要求 ≥2 次复现记录。
5. **夸大词一票否决**：主张含 `AGI/ASI/零幻觉/完全自治/替代律师/修复所有 bug/人工门 H=0` 等词且无 `E8` → 判 `INVALID_EXAGGERATED`，禁用一切现状表述。
6. **分数不折抵**：公式分数、基因数量、文件数、模型自评、历史 PASS 均不触发升级。

## 4. 状态派生表

读回时按有效证据链派生**允许的**状态词（不是自选标签）：

| 有效证据 | 派生状态 | 允许说 | 禁止说 |
|---|---|---|---|
| `E2+E3+E5+E6+E7+E8` | `VERIFIED` | 「在给定版本/环境/任务范围内经真实任务闭环验证」 | 长期稳定、SLA、通用有效 |
| 加上 `E9` | `VERIFIED_E9` | 「在说明的任务集/期间/协议下表现稳定」 | 永不失败、AGI/ASI、替代专业人员 |
| `E2+E3+E5`（缺 E7） | `IMPLEMENTED_NOT_WIRED` | 「实现并经局部验证，尚未证实运行时接线」 | 已部署、已启用、已接入、生产可用 |
| 有部分证据但链断 | `PARTIAL` | 「局部证据存在，最高可支撑 Ex，关键缺口未补」 | 把局部通过掩盖失败、把未运行写为通过 |
| 仅 `E0` | `HISTORICAL` | 「历史记录/待重新核验」 | 作为当前资产、能力或部署凭据 |
| 含夸大词且无 `E8` | `INVALID_EXAGGERATED` | 「该表述无效/夸大」 | 任何现状、能力、部署表述 |

## 5. 用法

```bash
# 登记证据（不满足最低要求会被拒，exit=1）
python3 scripts/self_evolve.py --evidence CLM-001 --level E2 \
    --artifact scripts/self_evolve.py --note apply_gate

# 命令类证据：必须显式 --execute 才真跑
python3 scripts/self_evolve.py --evidence CLM-001 --level E5 \
    --artifact scripts/self_evolve.py \
    --verify-cmd "python3 tests/test_self_evolve.py" --execute

# 读回：重新核验 + 派生允许的状态词
python3 scripts/self_evolve.py --evidence-status CLM-001
python3 scripts/self_evolve.py --evidence-status CLM-001 --execute   # 重跑命令类

# 看等级定义
python3 scripts/self_evolve.py --list-levels
```

`--status` 会附带 `evidence` 概览（主张数/条目数）。账本落 `~/.pi/agent/evolution/evidence/ledger.json`（沙箱内，可删可回滚）。

## 6. 与门禁的分工

| | `docs/GATES.md`（五层门禁） | 本文件（证据账本） |
|---|---|---|
| 管什么 | 变更**能不能落**（备份/白名单/diff/密钥/危险模式） | 主张**凭什么说**（证据够不够） |
| 时机 | Apply 之前 | 任何时候，尤其是汇报之前 |
| 失败后果 | `BLOCKED`，不改 | 拒绝登记 / 降级状态词 |

两者互补：门禁防「乱改」，账本防「谎报」。**一个系统只有门禁没有账本，仍然可以拿文件存在冒充能力完成。**
