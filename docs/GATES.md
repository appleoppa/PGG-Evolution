# 门禁体系：五层门禁 + 三重进化门禁

> 来源：Geneclaw/GEP v0（五层门禁）+ 三重进化门禁（EVM缺陷治理/超级路由/GitHub工厂学习）
> 门禁是自进化闭环的刹车：**没有门禁的"进化"是自毁。**

## 1. 五层应用门禁（Apply 前必查）

| 层 | 检查 | 失败处理 |
|---|---|---|
| **L1 备份** | 变更文件已备份（带时间戳） | BLOCKED |
| **L2 allowlist** | 变更路径在白名单内 | BLOCKED |
| **L3 diff 大小** | patch 行数超限（evolution 模式 >200 行 / feature 模式 >2000 行） | BLOCKED |
| **L4 密钥扫描** | 无 token/key/secret 明文 | BLOCKED |
| **L5 危险模式** | 无 rm -rf/force push/生产切换 | BLOCKED |

**默认行为**：`allow_apply_default=false`（不批准就不应用）。

### L3 分模式（2026-09-20 苹果哥批准）

问题：改老逻辑与加新模块混在同一阈值下，导致「加功能」每次都被 200 行拦住。

```bash
python3 scripts/self_evolve.py --gate --gate-backup /tmp/bk                    # evolution（默认，200 行）
python3 scripts/self_evolve.py --gate --gate-backup /tmp/bk --gate-mode feature # feature（至 2000 行）
```

**防橡皮图章**：feature 模式放宽**不只靠声明**，必须同时满足两个可验证准入条件：

1. **零修改/删除行**——变更集必须是纯新增（`-` 行只允许出现在文件头 `+++`/`---`）
2. **变更路径全部是新增文件**——不存在于 HEAD（git status 为 `??` 或已暂存的 `A`）

任一不满足 → **自动退回 evolution 的 200 行阈值**（fail-closed），并在 `L3_diff_size` 里报
`feature_eligible: false` 与 `ineligible_reason`。feature 模式仍有 2000 行硬上限，不能无限放宽。

实测（2026-09-20）：修改 3 个已有文件共 174 行时，feature 模式正确报
`feature_eligible=false`、`ineligible_reason="存在修改/删除行（非纯新增）"`。

## 2. 三重进化门禁（每轮闭环必须输出）

### 门1：EVM 缺陷治理门

| 字段 | 说明 |
|---|---|
| 短板原文 | 来自真实代入/观察 |
| 缺陷类别 | 分类（如：哈希漂移/语义缺失/回路断裂） |
| 治理前数值 | 评测基线 |
| 治理后数值 | 评测结果 |
| 缺陷压降 | 变化量 |
| 剩余风险 | 未消除部分 |

阈值：缺陷率 ≥0.75 通过，<0.6 阻塞。

### 门2：超级路由决策门

| 字段 | 说明 |
|---|---|
| 主学习路径 | 首选来源 |
| 替代路径 | 备选 |
| 是否调用 GitHub 工厂 | 是/否 |
| 是否调用多模型反证 | 是/否 |
| 最小补齐动作候选 | 最小变更方案 |
| 失败修复路径 | 失败时怎么办 |

### 门3：GitHub 工厂学习门

| 字段 | 要求 |
|---|---|
| 实际来源 | 仓库+链接+star（可追溯） |
| 原文具体机制 | ≥50 字（读到原文，非搜索摘要） |
| 与短板对应关系 | 明确对应哪个短板 |
| 学习点改变补齐动作 | 学习后动作确实变了 |
| 参与等级 | 落地 > 判断 > 信息 > 通路 > 未参与 |

**核心规则**：辅助系统（EVM/路由/反证）必须产生**判断/信息/修复/反证**四种增量之一才算参与；仅"可访问/有分数"= 通路可用，不算参与。

## 3. 诚实审计标准（来自成果包 04 / 07）

证据分级已从「文档表格」升级为**可执行账本**，完整规格见 [`EVIDENCE.md`](EVIDENCE.md)。

| 级别 | 含义 |
|---|---|
| E0 | 文本主张（有人提过） |
| E1-E2 | 文件/代码存在 |
| E3-E4 | 可加载 / 测试存在 |
| **E5** | 局部测试通过（不等于可用） |
| E6-E7 | 入口可执行 / 运行时接线 |
| **E8** | 真实任务闭环（唯一可称 VERIFIED） |
| E9 | 长期稳定/外部评测（需 ≥2 次复现） |
| INVALID_EXAGGERATED | 含绝对化词且无 E8，禁用一切现状表述 |

**教训**：22 项概念当初 VERIFIED=0，全部仅 E5。分数/文件/报告都不能冒充 E8。

**现在可以真拦了**：

```bash
# 谎报工件/跳级/夸大词/空文件，全部会被拒
python3 scripts/self_evolve.py --evidence CLM-1 --level E1 --artifact /nope/x.py   # → BLOCKED
python3 scripts/self_evolve.py --evidence-status CLM-1                              # → 派生允许的状态词
```

## 4. 评估器必须先审自己

- 不能手写修复后分数
- 不能用同一治理系数重复自证
- 没有审错清单、修复动作、重新代入和边界声明，分数无效

## 5. 红线（永不放开）

- 法律最终意见/裁决、canonical memory 写入、权限/路由/安全策略/scheduler/凭据配置
- 进化只允许**提出候选变更**，经测试、审批、可回滚发布
- 不自动发布/扩权/改凭据/生产/法律输出
- kill switch：`SELF_EVOLUTION_PLUGIN_DISABLED=1`

## 6. 与证据账本的分工

门禁防「乱改」，证据账本（[`EVIDENCE.md`](EVIDENCE.md)）防「谎报」。
只有门禁没有账本，仍可拿文件存在冒充能力完成；只有账本没有门禁，仍可无备份地改生产。
