# 门禁体系：五层门禁 + 三重进化门禁

> 来源：Geneclaw/GEP v0（五层门禁）+ 三重进化门禁（EVM缺陷治理/超级路由/GitHub工厂学习）
> 门禁是自进化闭环的刹车：**没有门禁的"进化"是自毁。**

## 1. 五层应用门禁（Apply 前必查）

| 层 | 检查 | 失败处理 |
|---|---|---|
| **L1 备份** | 变更文件已备份（带时间戳） | BLOCKED |
| **L2 allowlist** | 变更路径在白名单内 | BLOCKED |
| **L3 diff 大小** | patch 行数超限（如 >200 行） | BLOCKED |
| **L4 密钥扫描** | 无 token/key/secret 明文 | BLOCKED |
| **L5 危险模式** | 无 rm -rf/force push/生产切换 | BLOCKED |

**默认行为**：`allow_apply_default=false`（不批准就不应用）。

## 2. 三重进化门禁（每轮闭环必须输出）

### 门1：EVM 缺陷治理门

| 字段 | 说明 |
|---|---|
| 短板原文 | 来自真实代入/观察 |
| 缺陷类别 | 分类（如：哈希漂移/语义缺失/回路断裂） |
| 治理前数值 | 评测基线 |
| 治理后数值 | 评测结果 |
| 缺陷压降 | 变化量 |
| 剩余风险 | 未消除部分 |

阈值：缺陷率 ≥0.75 通过，<0.6 阻塞。

### 门2：超级路由决策门

| 字段 | 说明 |
|---|---|
| 主学习路径 | 首选来源 |
| 替代路径 | 备选 |
| 是否调用 GitHub 工厂 | 是/否 |
| 是否调用多模型反证 | 是/否 |
| 最小补齐动作候选 | 最小变更方案 |
| 失败修复路径 | 失败时怎么办 |

### 门3：GitHub 工厂学习门

| 字段 | 要求 |
|---|---|
| 实际来源 | 仓库+链接+star（可追溯） |
| 原文具体机制 | ≥50 字（读到原文，非搜索摘要） |
| 与短板对应关系 | 明确对应哪个短板 |
| 学习点改变补齐动作 | 学习后动作确实变了 |
| 参与等级 | 落地 > 判断 > 信息 > 通路 > 未参与 |

**核心规则**：辅助系统（EVM/路由/反证）必须产生**判断/信息/修复/反证**四种增量之一才算参与；仅"可访问/有分数"= 通路可用，不算参与。

## 3. 诚实审计标准（来自成果包 04）

| 级别 | 含义 |
|---|---|
| E0-E4 | 静态/局部测试 |
| **E5** | 局部测试通过（不等于可用） |
| **E8** | 真实任务闭环证据（唯一可称 VERIFIED） |
| INVALID_EXAGGERATED | 概念夸大，排除 |

**教训**：22 项概念当初 VERIFIED=0，全部仅 E5。分数/文件/报告都不能冒充 E8。

## 4. 评估器必须先审自己

- 不能手写修复后分数
- 不能用同一治理系数重复自证
- 没有审错清单、修复动作、重新代入和边界声明，分数无效

## 5. 红线（永不放开）

- 法律最终意见/裁决、canonical memory 写入、权限/路由/安全策略/scheduler/凭据配置
- 进化只允许**提出候选变更**，经测试、审批、可回滚发布
- 不自动发布/扩权/改凭据/生产/法律输出
- kill switch：`SELF_EVOLUTION_PLUGIN_DISABLED=1`
